# Obsidian Circuit — Work 视觉系统规范

状态：已确认，待实现

版本：1.1

日期：2026-08-09

适用范围：`/work` 及其专属组件

## 1. 决策摘要

Work 使用独立于 Home、About 和 Blog 的视觉语言，主题名为 **Obsidian Circuit / 黑曜构域**。

系统由两部分组成：

- **Precision Grid** 是稳定骨架：负责网格、排版、内容层级、导航和组件边界。
- **Kinetic Type** 是表现层：仅用于 Hero、章节进入和关键标题等高价值时刻。

色彩使用黑曜石黑作为主背景、藏绿作为结构和局部表面、薄荷绿作为极少量交互信号。Work 保持科技感、简约、动态、高级和艺术性，同时避免常见的 AI 科技模板语言。

本规范替代项目此前关于“Work — 浅色技术图谱”的设计方向，并作为 Work 后续设计与实现的唯一正式依据。

## 2. 目标

- 让 Work 明显区别于全站暖纸母系统，但仍保留 Richard 的个人品牌连续性。
- 以真实项目、经历、技术关系和判断作为视觉内容，不用装饰性数据制造可信度。
- 建立可长期扩展的视觉底座，允许后续调整组件形态和动效节奏而不改变主题身份。
- 从 React Bits 借鉴“组件化动效”和“交互即反馈”的方法，不复制其网站、品牌或具体构图。
- 默认保持安静和可扫描；用户进入、聚焦或主动探索时，界面才显现能量。

## 3. 非目标

- 本规范不重排现有 Work 六个章节，也不改写内容数据。
- 本阶段不创建运行时主题文件、组件代码或新页面。
- 不建设通用后台组件库、表单系统、模态框系统或数据可视化平台。
- 不使用蓝紫渐变、玻璃拟态、霓虹赛博、圆角卡片墙或伪终端界面。
- 不发明项目指标、运行状态、坐标、版本号或技术熟练度百分比。

## 4. 设计原则

### 4.1 Structure first

先通过网格、比例、留白和分隔线建立秩序，再使用颜色与动效。即使移除全部动画，页面仍应完整、清晰且具有识别度。

### 4.2 Motion has a job

每段动画只承担以下一种职责：进入、建立关系、确认反馈或表达真实状态。无法归入其中的动画应删除。

### 4.3 Evidence over decoration

技术标签必须关联真实项目或经历；能力节点必须能展开证据；编号和状态必须具有导航或内容意义。

### 4.4 Energy is scarce

单个视口只允许一个主要动态焦点。信号色、粒子和持续动画都属于稀缺资源。

### 4.5 Stable by default

内容在静止状态下最清晰。悬停、滚动和指针响应的位移幅度小，不能让用户为了读取信息追逐界面。

## 5. 色彩系统

### 5.1 核心 token

| Token | 值 | 职责 |
| --- | --- | --- |
| `--work-canvas` | `#050708` | 黑曜石黑主背景 |
| `--work-surface-1` | `#08100C` | 一级表面与内容分区 |
| `--work-surface-2` | `#0B1711` | 藏绿结构层、证据面板 |
| `--work-ink` | `#EEF2EF` | 主标题和主要正文 |
| `--work-ink-muted` | `#88928D` | 次级正文与辅助信息 |
| `--work-line` | `#1B3025` | 网格、分隔线与默认边框 |
| `--work-signal` | `#8AD7AF` | 活跃状态、焦点和关键线路 |
| `--work-signal-dim` | `#315B46` | 已建立关系、非当前节点 |

### 5.2 使用比例

单个典型视口的目标面积比例：

- 黑曜石黑：约 68%。
- 藏绿表面与结构：约 22%。
- 文字：约 8%。
- 明亮信号色：不超过 2%。

比例是视觉预算，不要求逐像素计算。Hero 可减少藏绿表面面积，证据与系统章节可适度增加。

### 5.3 颜色规则

- 大面积背景禁止使用渐变；只有遮罩、透明度过渡或不可见的性能优化层可以使用渐变函数。
- 内容表面主要通过明度和 1px 结构线区分，不使用大阴影。
- `--work-signal` 不承担大面积填充。只有 active 导航点、小节点或进度完成状态可以小面积实心使用。
- 错误、警告和成功等语义颜色仅在真实状态出现时引入，不预先装饰页面。
- 文本对比度以 WCAG AA 为最低要求；低对比只允许用于非关键结构线。

## 6. 字体系统

| 角色 | 字体 | 使用范围 |
| --- | --- | --- |
| Display | `Instrument Sans` | Hero、章节标题、关键观点 |
| Body | `IBM Plex Sans` | 正文、项目摘要、经历说明 |
| Technical | `IBM Plex Mono` | 日期、编号、技术、真实状态 |
| 中文回退 | `Noto Sans SC` | 所有中文内容 |

Work 不使用衬线字体，以强化其相对其他模块的独立性。

### 6.1 字阶

| Token | 桌面建议 | 移动建议 | 用途 |
| --- | --- | --- | --- |
| `display-xl` | `clamp(72px, 11vw, 176px)` | `clamp(48px, 16vw, 88px)` | Hero 动态标题 |
| `display-lg` | `clamp(56px, 8vw, 112px)` | `clamp(42px, 13vw, 72px)` | 章节标题 |
| `heading-md` | `clamp(28px, 4vw, 48px)` | `30–38px` | 模块标题 |
| `body-lg` | `18–20px` | `17–18px` | 观点和引导正文 |
| `body` | `16px` | `16px` | 默认正文 |
| `meta` | `10–12px` | `11–12px` | 技术与状态信息 |

### 6.2 排版规则

- 展示标题使用 `font-weight: 650–760`、负字距和紧行高；只允许一层描边标题。
- 正文行长控制在 45–72 个拉丁字符或约 24–36 个中文字符。
- 等宽字体不用于普通正文，也不用于重复展示同一信息。
- 英文大写只用于短标签，不用于超过一行的说明。
- 描边文字必须同时存在可读的实心文本状态；reduced-motion 下直接显示最终清晰状态。

## 7. 网格、空间与形状

- 大屏使用 12 栏网格，中屏 8 栏，小屏 4 栏。
- Work 内容最大宽度为 `1280px`，超宽屏保持居中，不无限拉伸。
- 页面安全边距：移动 `20px`、平板 `24–32px`、桌面 `32–64px`。
- 基础空间单位为 `4px`，常用节奏为 `8 / 12 / 16 / 24 / 32 / 48 / 64 / 96`。
- 组件圆角限制为 `0–2px`。圆形仅用于节点、轨道和明确的点状导航。
- 分隔线默认 1px；焦点描边 2px；不使用装饰性粗边框。
- 每个章节只有一个视觉主轴，避免同时使用大字、轨道图、粒子和多层卡片竞争注意力。

## 8. 组件体系

完整组件定义见 [`components.md`](./components.md)。组件分为六层：

1. 主题与结构。
2. 导航与进度。
3. 基础视觉原语。
4. 内容与证据组件。
5. 页面组合模块。
6. 动效原语。

组件实现必须保持单一职责。主题 token 不包含组件布局；基础组件不反向承担章节数据；组合模块通过明确的 props、slots 或数据结构组装。

## 9. 动效系统

精确参数、时序、性能预算和 reduced-motion 行为见 [`motion.md`](./motion.md)。Work 与其他页面之间的点聚焦穿梭转场见 [`theme-transition.md`](./theme-transition.md)。总体规则：

- Precision Grid 组件默认静止。
- Kinetic Type 只出现在 Hero、章节标题和少量状态建立时刻。
- 同屏最多一个持续动画对象。
- 指针视差、磁吸和粒子只在精确指针设备启用。
- 所有信息在无动画时仍完整可用。

## 10. 响应式系统

完整规则见 [`responsive.md`](./responsive.md)。响应式不是简单缩小桌面版，而是按信息优先级重新排列：

- 移动端将固定侧轨改为底部章节导航。
- 能力关系图降级为分组列表与证据展开。
- 项目行和时间线保留线性扫描结构，不转换为卡片墙。
- 短视口允许章节自然增高，不能为了满屏效果裁切内容。
- 触控设备不依赖 hover 暴露信息。

## 11. 内容语言

- 中文承担观点、人物表达和解释；英文承担短标签、技术和结构。
- 同一信息不做中英双重重复。
- 可使用 `PROFILE`、`SYSTEMS`、`SELECTED WORK`、`EXPERIENCE` 等真实章节标签。
- 禁止装饰性 `ONLINE`、`SYNCING`、坐标和随机哈希；只有真实状态存在时才显示状态标签。
- 项目摘要优先回答问题、角色、决策和结果，不罗列无上下文的技术栈。

## 13. 可访问性与性能底线

- 所有交互目标最小 `44×44px`。
- 所有交互元素提供清晰的 `:focus-visible` 状态。
- 键盘能够访问章节导航、能力节点和所有项目入口。
- `prefers-reduced-motion: reduce` 下取消粒子、持续动画、视差和强制滚动吸附。
- 不把 hover 作为获取内容的唯一方式。
- 动画优先使用 `transform` 和 `opacity`，避免滚动期间反复触发布局。
- 非首屏交互组件使用可见时加载或进入视口后启动；离开视口或页面隐藏时暂停。

## 14. 验收标准

- Work 与其他模块具有明确的独立身份，但 Header、Footer 和站点入口仍连续。
- 黑曜石黑为主底，藏绿承担结构，明亮信号色面积受控。
- 移除动画后，页面层级、导航和内容仍完整。
- 页面不存在圆角卡片墙、蓝紫大渐变、玻璃拟态和伪终端装饰。
- 组件覆盖当前 Hero、Who am I、Systems、Projects、Experience 和 More 六个章节。
- 所有动态组件具有 reduced-motion 方案和停止条件。
- 手机、平板、桌面和短视口均没有内容裁切或必须 hover 才能访问的信息。
- 项目、技能和经历只展示真实数据；缺失内容使用诚实的 Empty State。
