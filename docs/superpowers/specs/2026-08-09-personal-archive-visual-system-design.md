# Richard Personal Archive — 统一视觉系统设计规格

状态：待用户最终审阅  
日期：2026-08-09  
实施方式：后续由 Luna 按阶段执行  

## 1. 项目定位

这个网站首先是 Richard 长期维护的个人博客与成长档案，其次用于证明大四阶段的技术能力，并为潜在雇主、合作伙伴和技术同行提供清晰入口。

核心人格比例：

- 独立创造者 40%：对技术、设计和新想法保持好奇。
- 系统建造者 30%：能够把复杂、混乱的问题整理为稳定清晰的系统。
- 安静记录者 30%：愿意保留成长过程、观察和未完成的想法。

品牌核心表达：

> 一个持续整理复杂世界、保持好奇，也认真记录成长的独立创造者。

内容优先级：

1. 长期个人档案。
2. 求职与技术能力证明。
3. 同行交流与潜在合作。

## 2. 设计目标

- 首页采用 Claude 式的高级、克制、清晰与大留白，但不复制其品牌标识或具体构图。
- About 页面采用“生长笔记”表达人的经历、变化和仍在发展的想法。
- Work 页面采用“浅色技术图谱”，集中表达工程能力和技术可信度。
- Blog 页面采用“安静的阅读档案”，让内容长期可读，而不是成为视觉展示场。
- 四个页面共享同一品牌母系统，但允许各自使用不同的视觉方言。
- 主要设计感来自比例、排版、留白、真实内容和节奏，不依赖大量装饰小字。
- 页面和组件保持模块化，后续修改单一页面或模块时不牵动全站。

## 3. 非目标

- 不把整站做成 Claude、喜茶或其他品牌的复刻品。
- 不使用霓虹赛博、玻璃拟态、强渐变和仪表盘式信息堆叠制造“科技感”。
- 不在每个区块堆放坐标、状态、批注、英文缩写或无意义编号。
- 不把首页做成动画简历，也不把 Work 做成技术栈清单。
- 不发明不存在的经历、项目数据、用户评价或技术成果。

## 4. 品牌母系统

### 4.1 色彩

全站使用一套基础色，页面只改变使用比例。

| Token | 建议值 | 用途 |
| --- | --- | --- |
| `paper` | `#F4F0E8` | 全站暖纸背景 |
| `surface` | `#FAF8F3` | 卡片、文章与局部浮层 |
| `ink` | `#1D1D1A` | 标题与主要正文 |
| `ink-soft` | `#6E706A` | 次级正文 |
| `border` | `#D8D2C7` | 分隔线与网格 |
| `sage` | `#64745D` | 理性、系统与当前状态 |
| `terracotta` | `#C97858` | 灵感、人物温度与重点词 |
| `steel` | `#6F7F86` | Work 页面技术关系 |

规则：

- 单屏最多出现一个主要强调色。
- 陶土橙不承担大面积背景。
- Work 的科技感由钢蓝、线条密度和空间结构产生，不使用高亮霓虹。
- 正文与背景必须维持清晰对比，低对比只允许出现在非关键装饰中。

### 4.2 字体角色

建议使用开源字体，实施前确认加载性能与中文字形覆盖：

- 展示衬线：`Newsreader`，中文回退 `Noto Serif SC`。
- 正文无衬线：`IBM Plex Sans`，中文回退 `Noto Sans SC`。
- 技术与编号：`IBM Plex Mono`。

规则：

- 衬线字体只用于标题、文章标题和少量重点句。
- 正文保持无衬线，避免页面过度文学化。
- 等宽字体只用于真实的日期、技术、索引和状态信息。
- 移动端辅助文字不得小于 12px，正文不得小于 16px。

### 4.3 网格与空间

- 桌面内容最大宽度：1184px。
- 桌面使用 12 栏网格，页面左右安全边距随窗口在 32–64px 之间变化。
- 平板使用 8 栏网格。
- 移动端使用 4 栏网格，左右边距 20px。
- 每一屏只设置一个主要视觉中心。
- 区块间通过空间和一条明确分隔关系组织，不用多层卡片包裹。

### 4.4 语言系统

中文负责情绪、观点和记忆点；英文负责结构、栏目和简短状态。相同信息不做中英重复翻译。

建议核心句：

- Home：`把复杂的事，慢慢做清楚。`
- About：`一些经历，一些还在生长的想法。`
- Work：`系统不是堆出来的，是一层层想清楚的。`
- Blog：`没有想完的，也先留下来。`

英文结构标签示例：

- `HOME`
- `ABOUT`
- `WORK`
- `NOTES`
- `SELECTED WORK`
- `EXPERIENCE`

小字约束：

- 每个内容区块最多一组辅助标签。
- 辅助标签必须承载日期、栏目、技术或状态等真实信息。
- 删除纯装饰性的 `ACTIVE`、坐标、伪系统状态和重复编号。

### 4.5 动效

- 动效关键词：克制、连续、轻盈、可预测。
- 页面首次进入可以保留一次 0.8–1.1 秒的短进度过渡；同一会话返回首页时跳过。
- Hero 完整显现控制在约 1.2 秒内，进度结束与内容进入允许部分重叠。
- 普通内容进入使用 300–600ms 的淡入、上移或遮罩揭示。
- About 可以使用缓慢生长的路径，但每屏最多一个持续运动对象。
- Work 可以使用架构线路绘制、节点建立和技能关系展开。
- Blog 不使用持续漂浮动画，阅读时保持稳定。
- 所有页面支持 `prefers-reduced-motion`，并保证关闭动效后信息完整。

## 5. 全局结构

### 5.1 顶栏

- 所有页面共享同一个 Header 组件与响应式边距。
- 左侧品牌始终使用 `Richard`，不增加第二个 Logo。
- 桌面导航为 Home、About、Work、Blog。
- 当前栏目仅使用细下划线或文字颜色变化，不加入圆角胶囊。
- 移动端使用简洁菜单面板，触控目标至少 44px。

### 5.2 页脚

- 保留版权、RSS、GitHub 和邮箱入口。
- 不重复页面主导航，不增加大型口号。
- 联系方式使用真实 `mailto:` 链接。

### 5.3 共享组件边界

- `SiteHeader`：品牌、桌面导航、移动菜单。
- `SiteFooter`：联系与外部入口。
- `PageHero`：共享基础布局，允许页面注入自己的视觉层。
- `SectionHeading`：标题、可选结构标签、说明文字。
- `ContentDivider`：统一的章节分隔关系。
- `MotionReveal`：共享进入动画与 reduced-motion 处理。
- `ArchiveLink`：统一文字链接、箭头与焦点状态。

页面专属组件不得反向承载全局逻辑。主题差异通过页面级 token 或 variant 注入，不复制全局组件。

## 6. Home — 克制序言

### 6.1 角色

首页只负责建立第一印象和分发入口，不完整展开履历、技能和文章内容。

### 6.2 Hero

建议主文案：

> 把复杂的事，慢慢做清楚。

辅助说明：

> 我是 Richard，一名正在成长的开发者。这里保存我做过的系统、走过的路径，以及还没有想完的事。

结构标签可以使用：`BUILDER · MAKER · NOTE KEEPER`

视觉规则：

- 大标题是唯一主角。
- 右侧不再放置与标题同等重量的伪工作台卡片。
- 右侧可以呈现一个真实的“当前内容”：最新项目、最近文章或当前研究主题，三者择一。
- 背景只保留一套线路或纸张关系，不同时叠加水彩、线路、节点、卡片和多个状态条。
- 首屏完整显示滚动提示，不露出下一章节内容。

### 6.3 首页内容顺序

1. Hero：一句身份表达与一个主入口。
2. About 摘要：一段不超过 80 字的自我介绍，链接至 About。
3. Work 摘要：一项代表性项目或当前方向，链接至 Work。
4. Blog 摘要：最近 2–3 篇文章标题，链接至 Blog。
5. Contact：简洁邮箱邀请。

三个摘要区块使用宽幅编辑式行布局，不使用三个相同圆角卡片。

## 7. About — 生长笔记

### 7.1 角色

About 讲述“为什么成为现在的 Richard”，重点是成长过程、判断方式和持续兴趣，不重复 Work 的技术证明。

### 7.2 视觉语言

- 暖纸底色比例最高。
- 使用一条贯穿页面的缓慢生长路径，连接关键经历。
- 允许少量水彩、纸张或扫描纹理，但一屏只出现一种。
- 标题排版可以更松、更有断句感；正文仍保持稳定阅读宽度。
- 不使用大量手写批注。需要强调时只保留一句较大的边缘短句。

### 7.3 内容顺序

1. Hero：当前的自我定义与一张可选真实照片或个人物件图。
2. 起点：为什么开始写代码、做项目或记录。
3. 成长路径：大学、实习、重要项目和认知变化。
4. 做事方式：面对复杂问题时如何理解、拆分和完成。
5. 当前状态：正在学习、正在构建、正在思考的内容。
6. 下一步：希望成为怎样的工程师与创造者。

经历使用 3–5 个关键节点，不制作密集简历时间轴。

## 8. Work — 浅色技术图谱

### 8.1 角色

Work 负责证明能力。科技感来自真实的系统关系、技术决策与结构表达，而不是视觉特效。

当前 Work 页面已有的动态 HeroReactive 作为既有入口保留，本轮不替换。浅色技术图谱从 Hero 下方的经历、技能和项目区域开始，负责把动态第一印象转化为可验证的技术证据。

### 8.2 Hero

建议主文案：

> 系统不是堆出来的，是一层层想清楚的。

Hero 提供三项真实摘要：

- 当前技术定位。
- 主要关注方向。
- 可验证的代表项目数量或经历阶段。

如果没有真实量化信息，使用文字事实，不填充虚构数字。

### 8.3 实习与工作经历

- 按时间逆序展示。
- 每段经历只表达：背景、职责、关键问题、自己的决策、结果。
- 公司、职位和日期清晰可扫描。
- 技术标签最多 4–6 个。
- 当前数据中的 `Your Company` 等占位内容必须在上线前替换或隐藏。

### 8.4 技术栈放射图

保留现有放射图思路，但让关系可解释：

- 中心：Richard / Software Engineering。
- 第一圈：Backend、Frontend、Infrastructure、Tooling。
- 第二圈：对应的真实语言、框架和平台。
- 节点大小表示熟悉程度，连线表示实际组合使用关系。
- 点击或键盘聚焦某个节点时，在固定信息区显示相关项目证据。
- 不用自评五星或纯主观百分比。
- 移动端降级为可扫描分组列表，不强行压缩放射图。

### 8.5 项目案例

项目是 Work 的核心，每个项目使用统一案例结构：

1. 问题：为什么要做。
2. 角色：本人负责什么。
3. 系统：核心模块和数据流。
4. 决策：最重要的 2–3 个技术判断。
5. 结果：可验证的完成情况、性能或使用结果。
6. 复盘：现在会如何改进。

项目列表首页只展示摘要，点击进入独立案例页。案例图优先使用真实截图、架构图和运行结果，不使用无意义抽象插画替代产品。

## 9. Blog — 安静的阅读档案

### 9.1 角色

Blog 是长期积累区，视觉服务于阅读、检索和再次访问。

### 9.2 列表页

- 顶部只有一句短介绍和文章数量。
- 文章按年份分组，保持当前 Archive 方向。
- 列表项显示标题、日期、简短摘要和最多两个标签。
- 分类筛选使用普通文本，不做复杂筛选面板。
- 不使用封面图网格，除非文章确实依赖视觉内容。

### 9.3 文章页

- 正文宽度约 680–760px。
- 标题、摘要、日期之后立即进入正文。
- 代码、引用、图片和小标题拥有稳定且克制的层级。
- 侧边只允许一个阅读辅助模块，例如目录或阅读进度，二者择一。
- 文章结束提供上一篇、下一篇和返回档案入口。
- 不加入持续运动、漂浮装饰或与阅读无关的状态标签。

## 10. 内容准备要求

视觉实施前必须先清理模板内容。当前项目至少需要补齐：

- 真实且大小写正确的个人职位描述。
- 80 字以内的首页简介。
- About 的 3–5 个成长节点。
- 真实实习或工作经历。
- 真实技术栈分组及对应项目证据。
- 至少 2 个可展开的项目案例；不足时宁可少展示，不制造占位项目。
- Blog 的真实文章标题、摘要和标签。
- 正确统一的邮箱与 GitHub 信息。

在内容未准备完整时，Luna 应使用明确的结构占位标识，不编造事实。

## 11. Luna 执行阶段

为降低改动耦合，后续实施按以下顺序进行，每个阶段独立验收：

### 阶段 0：内容清理

- 修正个人资料和占位数据。
- 建立 Experience、Project、Skill、Post 的清晰内容契约。
- 确认没有虚构内容进入页面。

### 阶段 1：品牌母系统

- 落地颜色、字体、空间和动效 token。
- 统一 Header、Footer、PageHero、SectionHeading 和链接样式。
- 建立页面级 theme variant，不复制全局组件。

### 阶段 2：Home

- 简化现有 Hero 的双主角结构。
- 重构 About、Work、Blog 三个首页入口。
- 缩短加载与分段显现时间。

### 阶段 3：About

- 实现生长路径、关键经历和当前状态。
- 将水彩与纸张纹理限制在 About 页面。

### 阶段 4：Work

- 实现浅色技术图谱 Hero。
- 实现实习/经历模块。
- 重构技能放射图及移动端列表降级。
- 实现项目摘要与案例结构。

### 阶段 5：Blog

- 完成安静档案列表。
- 统一文章排版、代码块和文章导航。

### 阶段 6：整体验证

- 桌面、平板、移动端视觉检查。
- 键盘导航、焦点状态与语义结构检查。
- `prefers-reduced-motion` 检查。
- 字体、图片和动画性能检查。
- 确认页面之间有统一品牌感，但没有视觉复制。

## 12. 验收标准

- 用户在首页 5 秒内能理解 Richard 是谁、做什么以及网站包含什么。
- Home、About、Work、Blog 可被辨认为同一网站，同时具有清晰不同的页面性格。
- 任一普通区块不超过一组辅助小字。
- Work 的技术信息全部能由真实经历或项目支持。
- 移动端不存在侧边导航压住正文、微型标签不可读或桌面构图直接压缩的问题。
- 首页首次进入至主要内容可读不超过约 1.5 秒；同一会话返回时不重复阻塞。
- Blog 正文在无动画和无装饰的情况下仍具有完整层级与良好阅读体验。
- 关闭 JavaScript 或启用 reduced motion 后，核心内容和导航仍然可用。
- 修改单一页面的视觉模块时，不需要改动其他页面的专属组件。

## 13. 已确认决策

- Home：Claude 式高级克制。
- About：生长笔记。
- Work：浅色技术图谱。
- Blog：安静的阅读档案。
- 语言：中文表达情绪，英文承担结构，不做重复翻译。
- 个性比例：系统建造者 30%、独立创造者 40%、安静记录者 30%。
- 避免大量批注型小字。
- 后续由 Luna 分阶段执行，本规格作为设计和验收依据。
