# Hero GPT Image 2 动图视觉设计

## 目标

在首页 Hero 左侧视觉区加入一张使用 GPT Image 2 生成的原创抽象插画，并通过轻量 CSS/React 动效形成“动图般”的持续运动感。视觉需要参考 Claude 产品页 Hero 的抽象手绘动画语言，但保持本项目已有的「喜茶拙趣 + Claude 温暖光晕」主题。

## 已确认的视觉方向

- 暖米白纸色背景，与现有 `--color-paper` 一致。
- 墨黑与低饱和墨绿手绘线条。
- 一个陶土橙色的有机焦点，呼应现有 `--color-warm`。
- 大面积留白、不对称构图、粗细不完全均匀的手绘线条。
- 不使用 Claude 的人物轮廓、Logo、文案或可识别品牌资产。
- 不生成文字，避免图片内文字渲染错误。

建议的画面主题是“思考轨道”：抽象线条围绕一个有机色块或圆形焦点，表达想法聚合、展开和形成。

## 页面集成

`HeroReactive.tsx` 继续作为 Hero 的唯一交互组件：

- 左侧现有手绘圆环替换为图片视觉容器。
- 右侧标题、副标题和 prompt 输入框保持现有结构。
- 图片使用 `public/hero-thinking-orbit.png`，通过普通静态路径引用。
- 图片采用 `loading="eager"`、明确宽高和 `alt`，避免首屏布局跳动。
- 视觉容器保持响应式：桌面端位于左栏，移动端位于内容上方或紧邻标题之前。

## 动效策略

GPT Image 2 输出的是静态位图，因此使用稳定的容器级动效模拟持续动画：

- 约 18–24 秒的慢速上下漂浮。
- 约 24–32 秒的极小角度旋转，幅度不超过 2deg。
- 现有全局暖色光晕继续负责环境氛围，不再叠加多层渐变。
- 只使用 `transform` 与 `opacity`，不触发布局重排。
- `prefers-reduced-motion: reduce` 时取消动画并显示静态图片。

不采用多帧交叉淡入：GPT Image 2 不保证连续帧的一致性，容易出现形体跳变；单张素材的维护和加载成本也更低。

## 验证标准

- `npm run build` 成功。
- Hero 首屏仍保持 `min-h-screen`，图片加载前后布局不跳动。
- 图片在桌面和窄屏均不遮挡标题、输入框或导航。
- 图片不包含文字、Logo、水印或 Claude 可识别资产。
- 常规模式有轻微持续动效，减少动效模式下保持静态。
- 图片引用位于项目 `public/`，不会依赖外部 CDN。
